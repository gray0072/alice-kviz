# 06. Техническая спецификация

## Архитектура

```
 Колонка (Станция Мини) ──голос──▶ Алиса (распознавание, синтез речи)
                                     │  POST JSON (протокол Диалогов 1.0)
                                     ▼
                           Yandex Cloud Function «alice-kviz» (Node.js)
                           index.js → src/handler.js → src/game.js
                                     │
                     data/questions/*.js (банк вопросов в коде)
```

- Сервера и базы данных нет. Состояние хранит Алиса и присылает его в каждом запросе:
  - `state.session` — текущая игра (живёт до конца сессии);
  - `state.application` — данные устройства: уровень и история вопросов (у каждой колонки свои).
- Функция без зависимостей: только Node.js 18 и новее, `npm install` не нужен.
- Обработчик работает в двух режимах:
  - **функция в Яндекс Облаке**: `event` — это сам запрос Алисы, ответ — объект (основной вариант);
  - **HTTP-вебхук**: `event.body` — строка JSON, ответ — `{ statusCode, body }`. Подходит для
    публичной функции или любого хостинга по HTTPS.

## Протокол

### Входящий запрос (нужные поля)

```json
{
  "version": "1.0",
  "session": { "new": true, "session_id": "…", "application": { "application_id": "…" } },
  "request": {
    "command": "второй вариант",
    "original_utterance": "Второй вариант",
    "type": "SimpleUtterance",
    "nlu": { "tokens": ["второй", "вариант"], "entities": [], "intents": {} }
  },
  "state": {
    "session": { "st": "q", "lv": 2, "ids": [418, 106], "i": 0, "sc": 0, "sl": 0, "ord": "tsr" },
    "application": { "lv": 2, "rc": [418, 106] }
  }
}
```

- Берётся `request.command` (Алиса уже убрала пунктуацию и перевела числительные в цифры), а если
  он пустой, то `original_utterance`.
- `original_utterance === "ping"` — служебная проверка Диалогов, навык отвечает `pong`.

### Ответ

```json
{
  "version": "1.0",
  "response": {
    "text": "…до 1024 символов…",
    "tts": "…с паузами sil <[400]>…",
    "end_session": false,
    "buttons": [{ "title": "1", "hide": true }, { "title": "2", "hide": true }]
  },
  "session_state": { "st": "q", "…": "…" },
  "application_state": { "lv": 2, "rc": [ … ] }
}
```

- `text` и `tts` обрезаются до 1024 символов. На практике самый длинный ответ около 500 символов,
  это проверяет `npm run validate`.
- Кнопки `hide: true` — подсказки. На Станции Мини их нет, в консоли и приложении они ускоряют тесты.

## Состояние

### `session_state`

| Поле | Тип | Смысл |
|---|---|---|
| `st` | `"level" \| "q" \| "end"` | шаг диалога |
| `lv` | `1 \| 2` | уровень текущей игры |
| `ids` | `number[5 \| 10]` | id вопросов игры в порядке показа |
| `i` | `number` | индекс текущего вопроса |
| `sc` | `number` | правильных ответов |
| `sl` | `number` | выбрано вредных советов |
| `ord` | `string` из `r`, `t`, `s` | порядок вариантов текущего вопроса, например `"tsr"`: 1 — подвох, 2 — вредный, 3 — правильный |
| `n` | `5 \| 10` | только в `end`: сколько вопросов было в игре (для «да» и кнопок) |
| `ch` | `1` | только в `level`: пришли из «поменять», голые «пять» / «десять» — это число вопросов |
| `rx` | `{ right, trick, silly, guessTrick, guessSilly, skipped: number[] }` | индексы последних реакций каждого типа, чтобы не повторять их (переносится между играми сессии) |

Размер — до ~400 байт (10 вопросов и память реакций), тест проверяет < 500.

### `application_state`

| Поле | Тип | Смысл |
|---|---|---|
| `lv` | `1 \| 2` | последний выбранный уровень |
| `n` | `5 \| 10` | последнее выбранное число вопросов (нет поля — 5) |
| `rc` | `number[]`, ≤ 60 | недавно заданные вопросы, от старых к новым |
| `hn` | `number` | сколько раз звучала подсказка «Чтобы поменять, скажи…» (после 3 — молчим) |
| `tt` | `number[4][≤10]` | индексы последних званий каждого уровня результата, чтобы не повторять их |

Размер — до ~400 байт. В настройках навыка нужно включить «Хранилище» (см. README), иначе Алиса
не будет присылать `state.application`. Тогда навык продолжит работать, только без памяти уровня,
числа вопросов и истории: каждый запуск будет начинаться с выбора уровня.

## Алгоритм подбора вопросов

`pickQuestions(level, recent, rng, length = 5, exclude = [])` в `src/selector.js`:

1. **Пул**: для уровня 1 — вопросы с `level: 1`, для уровня 2 — все вопросы. Минус `exclude` — вопросы,
   которые уже есть в текущей игре (когда игру удлиняют или меняют уровень посреди игры).
2. **Свежесть**: из пула убираются `recent`. Если осталось меньше 20, из `recent` выбрасывается
   старшая половина, и шаг повторяется.
3. **Тасование** Фишера — Йетса.
4. **Жадный набор с ограничениями**: все места (`place`) в игре разные, не больше 40 % вопросов на одну
   тему (`topic`): 2 из 5, 4 из 10. Если с ограничениями не набирается, добор идёт без них.
   - Уровень 2: сначала 60 % вопросов уровня 2 (3 из 5, 6 из 10), остальные любые, итог ещё раз перемешивается.
5. Выбранные id дописываются в `recent` (`rememberRecent`, лимит 60).

Порядок вариантов: для каждого вопроса `shuffle(['r','t','s'])`. Результат хранится в `ord`, чтобы
при «повтори» порядок не менялся.

## Распознавание ответа

`parseAnswer(utterance, options, entities)` в `src/matcher.js`:

1. Нормализация: нижний регистр, `ё` → `е`, убрать знаки.
2. **Номер.** Если реплика короткая (до 3 слов) или в ней есть «вариант», «ответ» или «номер», и
   найдено ровно одно число 1–3 (словом, цифрой, порядковым или сущностью `YANDEX.NUMBER`), это номер.
3. **Пересказ.** Слова реплики и вариантов приводятся к «основам»: стоп-слова выбрасываются, слова
   длиннее 5 букв обрезаются до 5. Побеждает вариант с наибольшим числом общих основ, если он
   единственный лидер и совпадений не меньше одного.
4. Если пересказ не сработал, но в длинной реплике ровно одно число, это номер.
5. Иначе `null`: Алиса переспрашивает.

### Настройки

`parseSettings(utterance, { strict, bareCount })` возвращает `{ lv, n, bad, marked }`:

- `n` — 5 или 10, только если рядом слово «вопрос», «задача», «задание» («десять вопросов», «10 задач»)
  или сказано «подлиннее» / «покороче». Без такого слова «десять» — это возраст («мне десять» →
  сложный уровень). Исключение — `bareCount` после «Что поменяем?».
- `bad` — названо другое число вопросов («семь вопросов»): Алиса говорит, что можно 5 или 10.
- `strict` (в состоянии `q`): каждое слово реплики должно быть из словаря настроек, а уровень узнаётся
  только по точным формам («сложный», «сложном», «посложнее»), не по корню. Так «сложить вещи», «это
  сложно», «просто подождать» остаются ответами.
- `marked` — реплика точно про настройки (два слова и больше или «полегче», «покороче»). Голое
  «сложный» сначала пробуется как пересказ ответа.

### Команды

Команды (`detectCommands`) ищутся только в репликах до 4 слов, а в состоянии вопроса — только после
попытки распознать ответ (см. [03-dialog-flow.md](03-dialog-flow.md#порядок-разбора-реплики-в-вопросе)).

## Нефункциональные требования

| Требование | Как выполнено |
|---|---|
| Ответ за 3 с | вся логика в памяти, холодный старт функции — десятки миллисекунд |
| Ответ ≤ 1024 символов | короткие тексты, проверка в `validate` и тестах, обрезка в `handler` |
| Нет персональных данных | навык не спрашивает имён и ничего не отправляет наружу, хранит только id вопросов |
| Стоимость | бесплатный уровень Cloud Functions с большим запасом покрывает домашнее использование |
| Воспроизводимость тестов | генератор `seeded(seed)` вместо `Math.random` |

|---|---|---|
