# 07. Тестирование

## Автоматические проверки

| Команда | Что проверяет |
|---|---|
| `npm test` | распознавание номеров («давай второй»), пересказов, уровней, числа вопросов и команд; смена уровня и числа вопросов посреди игры и в конце, память настроек между запусками, подсказка только первые 3 раза, реакции без повторов в серии из трёх; что каждый вариант из банка, сказанный целиком, засчитывается как нужный ответ; подбор (5 разных, уровни, разнообразие, без повторов, забавный вопрос в каждой игре, когда их от 30); полную игру, итог с очками и званием, звания без повторов между играми, память уровня, «повтори», «не знаю», размер состояний (и `application_state` с четырёхзначными id), ping, HTTP-обёртку |
| `npm run validate` | число реакций (≥ 50 / 30 / 30), их длина, дубли и обращение без рода; число званий (≥ 20 на уровень), дубли и обращение без рода; поля и уникальность id, первая цифра id = набор (три или четыре цифры), существующие места и темы, `focus`, `pole`, `skill`, `fun` и `kind` из допустимых, места и наборы из `tools/targets.js`, длины текстов, совпадающие варианты, числительные в вариантах, длина самого длинного ответа ≤ 1024 |
| `npm run play` | ручная игра в терминале, как на колонке (`-- --tts` — показать разметку голоса, `-- --seed 5` — повторяемая игра) |

Перед каждой загрузкой новой версии: `npm test && npm run pack` (`pack` сам запускает `validate`).

## Проверка в консоли Диалогов

Вкладка «Тестирование» в консоли навыка работает до публикации.

1. Пустой запуск (первый раз) → приветствие и выбор уровня.
2. «лёгкий» → «Первый вопрос…», три варианта.
3. Ответить цифрой, словом («второй») и пересказом.
4. «повтори», «не знаю», «помощь» в середине игры.
5. Пройти 5 вопросов до итога (очки, звание, «Сыграем ещё?»), затем «да» → новая игра без повтора вопросов.
5а. Посреди игры «десять вопросов» → игра удлинилась; «полегче» → дальше лёгкие вопросы, очки на месте.
6. «хватит» → прощание со счётом.
7. Закрыть и открыть тест заново → игра сразу начинается с прошлыми уровнем и числом вопросов, без вопроса
   про уровень (если включено хранилище).

## Чек-лист на колонке

| # | Сценарий | Ожидание |
|---|---|---|
| 1 | «Алиса, запусти навык „Папин квест“» | навык открылся, звучит приветствие |
| 2 | Шестилетний ребёнок говорит «лёгкий» | Алиса поняла с первого раза |
| 3 | Ребёнок отвечает «два» / «второй» / «давай второй» | ответ засчитан |
| 4 | Ребёнок пересказывает ответ своими словами | ответ засчитан или Алиса переспрашивает, без ошибочного зачёта |
| 5 | Ребёнок молчит | колонка закрывает навык, при новом запуске игра начинается заново |
| 6 | Две колонки одновременно, разные уровни и число вопросов | игры не мешают друг другу, у каждой свои настройки при следующем запуске |
| 6а | Ребёнок говорит «десять вопросов» или «сложный уровень» посреди вопроса | Алиса поняла это как настройку, а не как ответ |
| 7 | «Алиса, хватит» посреди вопроса | навык закрыт |
| 8 | Темп речи и паузы | шестилетка успевает дослушать три варианта; если нет — увеличить `pause()` в `src/game.js` |
| 9 | Произношение | слова с неправильным ударением исправить в `tts` (знак `+` перед ударной гласной) |

## Как читать логи

В Yandex Cloud: функция → «Логи». Каждый вызов виден с длительностью. Ошибки JavaScript попадают
туда же. При ошибке Алиса говорит «Навык не отвечает».
